## 扫码模块方案（参考 E:\workspace\schedule-system-v2）
- 教务网基址 `https://kdjw.hnust.edu.cn`，链路 4 步且**必须共用同一 Cookie 会话**：
  1) `GET /Logon.do?method=QrCodeCreate&uuid={U}` → 二维码 JPEG + Set-Cookie(bzb_njw、SERVERID)；U 是我们自己生成的 16hex
  2) `GET /Logon.do?method=checksfhd&sid={U}&_={ts}` → 文本 `0`未扫 / `1`已扫待确认 / `2`|`yes`已确认
  3) `GET /Logon.do?method=logon_kd&type=wx&sid={U}` → **必须禁自动跟跳**，手动逐跳拿 Location，第 3 枚 Cookie 在中转里
  4) `GET /jsxsd/grsz/grsz_xggrxx.do` → 正则 `name="account"`=学号、`name="realName"`=姓名
- 三个不可省细节：UA 必须伪装浏览器；Cookie 全链路连续；`type=wx`（微信扫码，学校身份背书）。
- 参考实现是有状态长驻服务（内存 map + cookiejar + goroutine ticker），**与边缘函数模型冲突**。

## EdgeOne 官方能力（已核实，2026-09 文档）
- Edge Functions：仅 JS(ES2023+)/V8；代码包 5MB；body 1MB；**CPU 200ms/次（不含 I/O 等待）**；300 万次/月；提供 Fetch/Cookies/Web Crypto/waitUntil；路由大小写敏感、静态资源优先。
- Cloud Functions：body 6MB；**最大执行 30s（可配到 120s）**；代码包 128MB（可带依赖）。
- KV：1GB / 单值 1MB / **默认 TTL 60s / 最终一致性**（写后其他节点等缓存过期）→ **不能做「读-改-写」状态机**。
- 已知坑：EdgeOne `fetch` 用 `redirect:'follow'` 时**不记录中转 Set-Cookie**（需 `redirect:'manual'` 手动跟）——恰好与参考实现的禁跟跳写法一致。

## 推荐方案（待 POC 验证）
- **方案 A：无状态 Cookie 加密前移**（首选）——不存任何状态，Edge Function 把 `uuid+cookie串+ts` 用 **AES-GCM** 加密成 `seal` **返回给前端**（sessionStorage 保管），下次轮询带回。零 KV 依赖。成立前提：前端轮询本身是 `setTimeout` 串行（`QrLogin.vue` 即如此），天然无并发。
- 接口 3 个：`POST qr/start` → `{sessionId,qrcode,expiresIn:300,seal}`；`POST qr/poll` → `{status}`；`POST qr/verify` → `{studentId,name,applyToken}`。
- 状态机：pending→scanned→confirmed→(verify)→success/error；教务网异常时**返回 pending 不返回 error**。
- **跨云唯一耦合点**：共享密钥 `QR_COOKIE_KEY`（仅 EdgeOne）+ `QR_SIGN_SECRET`（EdgeOne 签 / Cloudflare 验，HS256 JWT，payload={sid,sub:学号,name,iat,exp,aud}）。两边都是 JS，验签代码可共享。
- 备选：B) Edge Functions + KV 存会话（受一致性拖累）；C) Cloud Functions 30~120s 一体化；D) 国内轻量服务器跑原 Go 服务（兜底，几乎零改造）。
- **POC 第 1 枪（定生死）**：Edge Function `fetch` 能否读到教务网响应的 `Set-Cookie`。读不到则 A 不成立，退 B/C/D。
- 合规：只取学号+姓名，绝不落库 cookie/密码；需取得指导老师或教务部门许可。

## 流量切换方案（Cloudflare 主站 + 国内 serverless 降级）
- 关键事实：`qr/poll` 占「加入我们」接口 **95%+ 的 QPS**（2s×300s×人数），且它本来就必须在国内 → 高峰压力天然已由 EdgeOne 承接。
- 切换载体优先级：**运行时配置**（D1 `site_config` → KV `runtime-config` → `GET /api/config/runtime`，`no-store`）> 自有域名 DNS 切换（前端零改动、无灰度）> Cloudflare 反代（仅灰度用）。
- **不要用 Cloudflare 反代承载生产流量**：用户→CF 海外→EdgeOne 国内，多绕一趟跨境，与提速目标相反。
- 前端 `src/api/client.ts`：双 base + **内置默认值兜底** + 幂等操作自动 failover + 定时/可见性重拉 config + 5xx 强制重拉。
- 跨云三坑：CORS 显式白名单（不能用 `*`）+ `OPTIONS` 预检；鉴权统一 `Authorization: Bearer`（**不用 Cookie**）；`X-Idempotency-Key` 去重；`shared/` 放唯一一份契约类型 + Zod。
- **D1 是唯一事实源**；若要切"写"，采用削峰缓冲（EdgeOne 受理即返回 + 国内队列 + 异步落 D1），而非搬数据库。

## 用户报「拒绝访问」的排查（2026-09-24 下午）
排查结论（都是环境因素，不是代码问题）：
- 当时 **8787 未监听**（后端没起）、**3000 被 IDE 内部服务占用**（`~/.workbuddy/binaries/node/.../node.exe server.mjs`，返回的 `/api/health` 是 `{stateless, uptimeSec, sealSecretSource...}` 这种别的服务结构）、本项目 `npm run dev` 也没在跑。
- 3000 上那个服务的 `/admin`、`/api/*` 都返回 404，`/` 是它自己的页面 —— 打开 3000 会看到**不是我们的站**。
- **5173 也被占用**，故前端 dev 端口改到 **5175** 并加 `strictPort: true`（已同步 README / HANDOVER / MEMORY.md）。
- 验证结果：Vite 在 5175 约 1 秒启动正常；后端 8787 用 `127.0.0.1` 与 `localhost` 都能通，`[::1]` 不通（wrangler 只绑 IPv4 loopback）。
- 下次遇到类似问题，先用 `Get-NetTCPConnection -LocalPort <port> -State Listen` 确认端口是否真的在监听，再看是不是撞到了别的服务。
- **根因**：用户的"拒绝访问"其实是**我把服务关掉了**——`scripts/smoke-api.ps1` / `probe-local.ps1` 的 `finally` 里原本 `Get-Process workerd | Stop-Process -Force` 会杀掉**所有** workerd，包括别人手动起的服务；而且脚本本来就是"测完即关"，用户随后打开网址必然连不上。已修：两个脚本改为**只清理自己启动的 workerd**（启动前先记录已有 PID，收尾时按差集清理）。
- **教训**：凡是"启动服务做验证"的动作，要么明确告诉用户服务已关闭、要么把服务留着并给出访问地址；不要留下"看起来在跑其实已经停了"的状态。
- 当前（2026-09-24 下午）已把开发服务常驻在后台：`npm run build` + `wrangler dev --port 8787`，访问 http://127.0.0.1:8787 ，账号 `admin` / `kingcola-dev-2026`。日志在 `dev-server.log` / `dev-server.err`。用户重启机器后需自行 `npm run local`。

### 追加修正（同日）：轮播图「不限大小」+ 图片版「只有图片」

### 追加修正 2（同日）：首屏两种类型尺寸/位置统一
